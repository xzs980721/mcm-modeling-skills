# 美赛建模工作流

## 动笔前：先取评奖标准简报

若环境中存在 `mcm-judge`（与本仓库同级的 `mcm-judge/SKILL.md`），在写 `plan.md` 之前先以 **brief 模式**产出 `reports/AWARD_BRIEF.md`。该文件给出评委预设怀疑清单、本题必须命中的动作（按"地板/强倾向"分层，附往年出现率）以及图表与版式底线。

`plan.md` 里的模型方向、图表规划与时间安排，应能逐条对上 `AWARD_BRIEF.md` 的动作清单；对不上的，在 `plan.md` 中写明理由。缺少该技能时跳过本步，按 `_references/math_modeling_norms.md` 执行。

## 启动与计划

1. 读取题面、附件和当届提交要求。确认题号、需要交付的各问与附加材料，记录缺失数据和关键歧义。
2. 沿用用户已指定的 Typst 或 LaTeX。选择会影响交付且尚未明确时询问。按美赛英文论文组织内容。
3. 在本次赛题项目中创建 `plan.md`，记录排版引擎、题目及任务数、模型方向、各阶段的负责人、输入和产物，以及关键假设或风险的检查方式。将「知识卡根目录」默认为相对技能仓库根目录的 `knowledge-cards/`，「原论文库路径」在用户未指定时记为待定。按[正文图件数量与计数](../_references/figure-workflow.md#正文图件数量与计数)规划正文图表数（分题号下限见[数值口径](../_references/thresholds.md)第一节）；概念图与数据图各自的下限见同一节，按题目确定具体配比。分析阶段补充逐问数学任务、共享基础和实际依赖。
4. 请用户按 [论文图表风格](../_references/figure-workflow.md#由用户选择整篇论文的图表风格) 确认全局配色。可用 ColorDrop 由关键词生成候选，也接受预设、自定义或参考图。将确认的 HEX 色值及用途写入 `plan.md`。总体解题路线图沿用锁定版式并使用全局配色。等待确认期间可以继续分析与求解。
5. 创建 `todo.md`。按下表逐阶段列出带 skill 名称的任务，完成且产物就绪后更新状态。

## 顺序与交接


| 阶段                   | 调用                 | 产物                                                                  |
| ---------------------- | -------------------- | --------------------------------------------------------------------- |
| 赛题分析与建模设计     | `2analysis-modeling` | `reports/ANALYSIS_MODELING_REPORT.md` 中的共享基础、逐问复用或扩展、验证与整合设计 |
| 求解、实验与数据可视化 | `3coding-visual`     | `code/`、`results/`、至少 5 张数据图（至少一张非常规）和含逐问结果及总体整合的 `reports/RESULTS_REPORT.md` |
| 背景、机制与流程图     | `4concept-visual`    | 至少 4 张概念图，含 Image2 文生图背景、总体解题路线图、机制图或系统工作图，以及 `reports/CONCEPT_FIGURES_REPORT.md` |
| 美赛论文写作与排版     | `5writing`           | 美赛模板下的`paper/` 源码和 PDF                                       |
| 提交前验收             | `6verify`            | `reports/VERIFY_REPORT.md`                                            |

按表顺序读取各阶段的 `SKILL.md`。依照 [建模方法优化流程](../_references/modeling-method-workflow.md)，先确定共用基础，各问能直接回答时复用。基础模型与每个必要扩展各自执行同一流程，先查阅知识卡、生成候选和验证资格，再设计两类图件并按可视化、创新性、效果筛选，最后由求解阶段复核。论文按赛题逐问展开并整合结论。分析阶段结束时，按 [图表工作流](../_references/figure-workflow.md) 在 `plan.md` 中登记各章图表的论证用途。阶段 3 和 4 按图件选择制作路线。图表生成后按各图件的规则做一轮独立的视觉迭代，排版后按实际尺寸复核。验收发现需要增补概念图时，回到阶段 4，更新论文后重新验收。

最终图表集中存放在 `figures/`。数据图、表格数值和定量结论应能追溯到计算结果。需要补充领域规范时，查看 [数学建模规范](../_references/math_modeling_norms.md)。

## 阶段自检

本阶段完成、进入下一阶段之前，调用 [mcm-judge](../mcm-judge/SKILL.md) 的 **check 模式**（Stage 1）：

1. 它按 `mcm-judge/references/stage-checks.md` 的 S1 节逐条核对，结果追加到 `reports/STAGE_CHECK.md`。
2. `verdict: return` 时，按它给出的不超过 3 条改法修，然后重跑核对；同一阶段最多 2 轮（见 [数值口径](../_references/thresholds.md)）。
3. 两轮仍 `return` 时，把未通过项写进"遗留"节并前进——缺口留痕，不要卡住。
4. 开始下一阶段前先读上一阶段的"遗留"节，确认已修。

这里不重复 `6verify` 的机检项（编译、章节结构、图件存在性），只判"这一步做对了没有"。
