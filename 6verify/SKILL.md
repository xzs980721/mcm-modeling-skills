# 验证和验收（Typst / LaTeX）

本 skill 是完整工作流的最后一关。它不重新建模、不生成新结果、不代替写作阶段重写论文；它负责发现硬错误、修复可直接修复的问题，并输出 `reports/VERIFY_REPORT.md`。

## 数学建模规范参考

如需领域判断，读取 `../_references/math_modeling_norms.md` 中的"论文验收与一致性"小节。该文件只是规范知识库，不是固定执行流程；具体目录、入口文件、结果文件和图表目录由当前项目结构决定。

## 阶段边界

- 本阶段负责：结构验收、文本质量门禁、图表引用检查、结果一致性检查、Typst/LaTeX 编译检查、PDF 视觉检查、提交清单。
- 本阶段不负责：重新设计模型、重新跑大规模实验、重新组织整篇论文。
- 发现硬错误时，优先做小范围修复；如果需要回到前序阶段，写入 `reports/VERIFY_REPORT.md` 并标记为未通过。

## 输入

由模型先根据当前工作区判断项目布局，再把实际路径传给检查脚本。常见输入包括但不限于：

1. 论文入口文件：`main.typ`（Typst）或 `main.tex`（LaTeX）。
2. 正文章节目录或若干正文文件（`.typ` 或 `.tex`）。
3. 参考文献文件（`references.typ` 或 `references.tex`）。
4. `plan.md` 中的论文图表风格与图表清单，以及前序分析、建模和结果报告、`reports/CONCEPT_FIGURES_REPORT.md`。旧赛题可沿用现有的 `reports/DRAWIO_REPORT.md`。
5. 图表目录
6. 可复现代码目录。
7. 编译后的 PDF，或可由入口文件编译得到的输出 PDF。

不要假设论文目录一定叫 `paper/`，也不要假设结果文件一定在项目根。若项目使用不同命名，按实际结构传参并在 `reports/VERIFY_REPORT.md` 中说明。

## 工作流程


### Step 1: 运行文本质量门禁

优先运行本 skill 的脚本。脚本按入口文件扩展名自动选择检查逻辑（`.typ` → Typst 检查，`.tex` → LaTeX 检查）：

```bash
set -o pipefail
mkdir -p _tmp
SCRIPT_PATH="<按当前 skill 实际位置确定>/scripts/writing_check.sh"
bash "$SCRIPT_PATH" \
  --paper-dir "$PAPER_DIR" \
  --main "$MAIN_FILE" \
  --sections-dir "$SECTIONS_DIR" \
  --references "$REFERENCES_FILE" \
  --figures-dir "$FIGURES_DIR" \
  --results-file "$RESULTS_FILE" \
  --problem-analysis "$PROBLEM_ANALYSIS_FILE" \
  --all-results "$ALL_RESULTS_FILE" \
  --internal-term CONCEPT_FIGURES_REPORT.md \
  | tee _tmp/writing_check.log
```

如果本 skill 被复制到其他目录，使用实际脚本路径。可以先运行 `bash <script> --help` 查看参数。不要把脚本路径、论文目录或文件名写死在验收逻辑中。

脚本只扫描文本，不生成论文，也不编译 PDF。它的 `FAIL` 属于硬错误，必须修复后重跑。

### Step 2: 章节数量和标题顺序

使用阶段 5 的内置模板时，按 [锁定正文一级章节](../5writing/SKILL.md#锁定正文一级章节) 执行严格核对。根据 `plan.md` 中的模板来源，运行 `python <5writing/scripts/check_sections.py 的实际路径> <论文入口> <原始模板入口>`。编译后再核对 PDF 的一级目录与正文标题、编号、顺序及页码。未经授权的偏离记为 `FAIL`，由阶段 5 修复并提交复验。若用户明确指定其他结构或官方要求造成例外，按 `plan.md` 记录的一级目录及依据核对，并把核对结果写入验收报告。

**Typst 引擎**检查：

- 入口 `.typ` 文件中 `#include "..."` 或 `#include("...")` 的数量是否与实际正文结构匹配。
- include 顺序是否符合文件名前缀顺序，例如 `1_...`, `2_...`, `3_...`。
- 每个 section 是否有明确一级标题（`= 标题`，等号后有空格）。
- 标题顺序是否符合所选论文类型。

**LaTeX 引擎**检查：

- 入口 `.tex` 文件中 `\input{...}` 或 `\include{...}` 的数量是否与实际正文结构匹配。
- 章节顺序是否符合文件名前缀顺序。
- 每个 section 是否有 `\section{}` 或对应级别标题。

通用检查（两种引擎）：

- 章节文件是否缺失、重复引用、未被引用。
- 对照题面及 `ANALYSIS_MODELING_REPORT.md` 核对求解章内的逐问小节，保留题面顺序、原有编号及未编号问询的可追溯标识。目录列出的逐问条目应与正文一致。核对是否出现独立的 `Model Selection` 模块或以候选总排名贯穿全文。

### Step 3: 图表和章节匹配

**Typst 引擎**检查：

- 图表目录中的 PDF 是否在正文中被引用。
- `#figure(image(...), caption: [...])` 的图片是否真实存在。图片路径必须相对于 `.typ` 文件。
- 数据图是否放在对应结果或分析章节。

**LaTeX 引擎**检查：

- `\includegraphics{}` 引用的图片文件是否真实存在。路径相对于 `.tex` 文件。
- `\caption{}` 是否存在。
- 数据图是否放在对应结果/分析章节。

通用检查（两种引擎）：

- 连续图表之间是否有足够解释文字。
- caption 是否过长、过泛或与图意不一致。
- 图表编号、正文引用和章节语义是否一致。
- 对照图表清单确认关键子问题、必要扩展和结论都有足够证据。检查背景图和示意图是否有明确用途及来源记录。
- 完整论文验收时，按[正文图件数量与计数](../_references/figure-workflow.md#正文图件数量与计数)核对最终 PDF 至少 12 张正文图，其中至少 4 张概念图和 5 张数据图，并按图号和用途登记。核对三类独立必需概念图均使用内置 Image2，其中背景图至少一张由纯文本生成。核对机制图及承担相同用途的系统工作图用 Image2 成稿，检查原图、提示词、核对记录和入稿文件对应关系。单独验收完整制图阶段时核对该类下限。
- 核对总体解题路线图与首次正文引用同在 `Introduction` 的总体思路小节。编译后复核 PDF 的阅读顺序，图和图题须完整出现在下一正文一级标题前。记录图号及页码，发现图浮动到后续章节时交 `5writing` 修正并复验。
- 完整论文验收时，在正文核对至少一张非常规数据图，参照 [mcm-data-figure](../mcm-data-figure/SKILL.md) 的图型判据和结果报告，检查数据来源、展示的额外关系或发现、定稿路径及实际尺寸下的可读性。
- 对照阶段 3 和 4 的报告，核查非常规数据图、机制阐释图或系统工作图的候选记录、原图定位和采用理由。候选不足时核对实际数量与原因。若图表卡均为常规图或均不适用，查看独立设计和图型取舍记录。核实数据图的定量矢量层来自当前结果和绘图代码，Image2 素材只承担非定量表达。
- 执行完整流程时，沿建模、结果和概念图报告核对最终基础模型的机制图或系统工作图。核对两种实质不同的视觉构思、选用理由、版式改动和缩印检查。确认成稿对应入选方案的论证目标、关键对象与已验证关系。按其能否讲清论文核心机制核对是否计入必需图。单独制图及沿用旧成果时可核对基于已采用模型补写的图件说明。
- 对照题面、正文和建模与结果报告逐问检查总体解题路线图。共享区仅呈现真实共用的模型或接口。每个小问恰有一个独立板块，流程图覆盖采用的主方法、必要扩展、关键步骤、输出和验证。跨板块联系体现实际依赖、共享输入或产出汇合。确认图内有可辨识的机制示意、辅助图片或插画。按论文实际尺寸核对拼写、编号、箭头方向、读序、对齐、留白和画面平衡。
- 按 [路线图母版](../mcm-solution-roadmap/references/image2-template.txt) 核对生成提示词及成稿。修订稿按 [局部修订与覆盖检查](../mcm-solution-roadmap/references/image2-prompt.md#局部修订与覆盖检查) 追溯最近通过核验的完整版与实际发送的完整提示词。对照逐问内容表和跨问连线表，在最终 PDF 尺寸确认每项公式、约束、独立步骤、结果、验证与连线仍可分别定位和阅读。成图保留共享区、逐问网格、板块内五步流程、实际依赖与最终综合区，并遵循母版的视觉规范。
- 对照 `plan.md` 的全局色板，核对路线图提示词内的 HEX 色值及用途，检查成图中主结构、分组和强调元素的颜色语义与全篇一致。发现明显偏色或语义错配时，交 `4concept-visual` 修正并复验。

不要生成 `*_typst_includes.typ` 或 `*_latex_includes.tex`；图表必须直接嵌在对应 section 中。

### Step 4: 写作质量和泄露检查

检查并修复：

- `TODO`、`PLACEHOLDER`、`待补充`、`待续写`、`示例数据` 等占位符。
- 论文正文出现内部工作流文件名、临时目录名、代码目录名或结果 JSON 路径。
- 过多列表式写作（Typst 中大量 `#list`、`enum`，LaTeX 中大量 `\begin{itemize}`、`\begin{enumerate}`）。
- 段落反复以"如图""由图""图 X 展示了"开头。
- 图表后没有解释、公式后没有变量含义、结论只报数不解释。

### Step 5: 数值和结果一致性

检查：

- 论文中的关键数值必须来自当前工作流声明的结果记录或结果 JSON。
- 目标函数值、误差指标、排名、权重、阈值、灵敏度结果不得与结果记录冲突。
- 逐问核对所需信息、数学任务、实际主方法、必要扩展、验证、答案与适用条件。每项扩展须解决明确的任务缺口。检查跨问引用、条件和单位是否相容，综合结论是否使用相应的已验证结果。共享基础修订时，检查受影响小问的重验记录。
- 在内部报告按 [建模方法优化流程](../_references/modeling-method-workflow.md) 分别检查共享基础及各必要扩展的入围判据与取舍。只有达标候选参加比较，排序依次为可视化潜力、创新性及效果。检查论文关键图能否以实际输出说明本问的机制或结论，并核对采用范文方法时的原文引用和迁移条件。
- 执行完整流程时，按 [基础模型候选的图件方案与评分](../_references/modeling-method-workflow.md#基础模型候选的图件方案与评分) 核对每个基础候选的两类文字方案，检查创意与美感的理由是否分别写到具体设计。合格候选的六项分数均须对应 0、1、2 分锚点与逐项依据，核对每类满分 6 分、等权合计满分 12 分，以及求解后是否按核验结果修订评分和交接记录。
- 检查正文的每项对照是否直接回答题目、解释扩展必要性或支撑验证结论，并在相应小问或验证小节出现。核对比较条件、效果差异、适用边界及未通过验证的情景。题面要求的方案比较或竞争解释检验可以独立完成该问。
- 如果存在汇总结果 JSON，抽取关键指标并确认论文正文中有对应结果。
- 公式中的符号应在符号说明或正文首次出现处解释。

发现数值冲突时，不要自行发明新结果；应回到结果记录或代码输出修正论文。

### Step 6: 引用和模板规范

检查：

- 参考文献文件是否存在，或模板是否采用了其他真实参考文献机制。
- 正文引用标记（Typst 的 `@label`/`#super`，LaTeX 的 `\cite{}`）是否能对应到真实参考文献。
- 图题、表题、摘要与正文统一使用英文。
- 选定的模板入口是否保留美赛所需的 Summary Sheet、编号、页眉页脚及当届提交格式。
- 不要把模板结构误删成普通空白文档。


### Step 7: 编译

**Typst 编译**：

```bash
command -v typst >/dev/null 2>&1 && typst compile "$MAIN_FILE" "$OUTPUT_PDF"
```

**LaTeX 编译**：

```bash
command -v xelatex >/dev/null 2>&1 && xelatex -interaction=nonstopmode "$MAIN_FILE" && xelatex -interaction=nonstopmode "$MAIN_FILE"
```

xelatex 需跑两遍解决目录和交叉引用。

编译失败必须修复语法、路径、图片引用或模板问题后重跑。编译通过后确认输出 PDF 非空。

### Step 8: PDF 视觉检查

本阶段默认具备视觉检查能力。将编译后的 PDF 逐页渲染为 PNG，并逐页打开检查。先查结构、溢出和字体问题，再复查全篇视觉风格与细节。

优先使用系统已有工具导出页面 PNG；不要为了视觉检查引入沉重依赖。可选命令示例：

```bash
mkdir -p _tmp/pdf-pages
if command -v pdftoppm >/dev/null 2>&1; then
  pdftoppm -png -r 160 "$OUTPUT_PDF" _tmp/pdf-pages/page
elif command -v mutool >/dev/null 2>&1; then
  mutool draw -r 160 -o _tmp/pdf-pages/page-%03d.png "$OUTPUT_PDF"
elif command -v magick >/dev/null 2>&1; then
  magick -density 160 "$OUTPUT_PDF" _tmp/pdf-pages/page-%03d.png
else
  echo "No PDF rasterizer found; record visual check as not run."
fi
```

导出后逐页检查：

- 页面是否空白、缺页、页数异常或页面尺寸异常。
- 标题、摘要、正文、页眉页脚、页码是否被裁切或位置明显错误。
- 表格是否超出页边距，单元格文字是否重叠、溢出、被截断。
- 图片、图题、表题、公式、编号是否与正文重叠。
- 公式是否越界，长公式是否压到页边距或下一段文字。
- 列表、段落、脚注、参考文献是否出现异常大空白、重叠或孤立残行。
- 中文/英文/数学符号字体是否明显缺字、乱码或 fallback 异常。
- 封面、摘要页、目录、附录等模板关键页面是否保留比赛要求的视觉结构。

完成上述检查后，按 `plan.md` 和 [图表工作流](../_references/figure-workflow.md) 做一轮全篇视觉复查：

- 通览页面缩略图，检查叙述和图表的节奏。按 [逐页图表覆盖要求](../_references/figure-workflow.md#正文逐页图表覆盖与版面平衡) 逐页确认从引言到结论的每一页都有服务于论证的可读图或表。对纯文字页记录 PDF 页码、章节和拟补的概念图、数据图或三线表，并在验收报告中标为硬错误。
- 逐页按实际阅读尺寸复查。统一图宽、对齐线、间距、图题与图例位置。修正参差的图组、偏离论证层级的大图、缩印难读的小图和拥挤的标签。
- 跨页对照字体、字号、颜色语义、标记、线宽和面板标签。核查初稿与定稿的代表性修改是否真正改善了可读性。

把需修正的问题记为页码、图表编号或段落、问题和处理方式。编排和三线表交给 `5writing`。增补或重做指定数据图用 [mcm-data-figure](../mcm-data-figure/SKILL.md)，涉及求解或数据问题时返回 `3coding-visual`。总体解题路线图、背景、机制和系统图返回 `4concept-visual`。路线图的提示词由 [mcm-solution-roadmap](../mcm-solution-roadmap/SKILL.md) 提供。同步更新图表清单及阶段报告，再由 `5writing` 更新图表标题和交叉引用并重新编译，以最终 PDF 逐页重验图表覆盖和全篇版面。

确实无法渲染或查看页面时，记录阻碍原因，至少检查 PDF 非空、页数和页面尺寸，并将视觉复核标为待完成。

### Step 9: 写验收报告

创建 `reports/VERIFY_REPORT.md`：

```markdown
# 验证和验收报告

## 结论
PASS / WARN / FAIL

## 检查项
| 检查项 | 结果 | 说明 |
| --- | --- | --- |

## 章节结构

## 图表引用

## 数值一致性

## 逐问答案、模型扩展与验证

## 跨问结果整合

## 图表覆盖与视觉迭代

## 文本质量门禁

## 编译

## PDF 视觉检查

## 全篇风格与细节复查

## 补图、重编译与复验记录

## 仍需处理的问题
```

硬错误清零、文本检查与编译通过，并完成结果、图表引用及视觉核对后才写 `PASS`。如果部分检查因工具或输入缺失而无法执行，给出 `WARN`，列出缺失项和已核查范围。

## 硬错误标准

以下问题必须判定 `FAIL`：

- 缺少选定的论文入口文件（`main.typ` 或 `main.tex`）或核心正文。
- 论文入口引用的章节文件不存在。
- Typst 入口缺少 `#include`；LaTeX 入口缺少 `\input`/`\include`。
- 正文章节缺少一级标题（Typst `= ` 后缺空格，LaTeX `\section{}` 缺失）。
- 章节顺序明显错误或重复。
- 论文遗漏明确问询的答案或证据支持的不可判定结论，或总体结论与所用小问的结果及适用条件冲突。
- 设置服务于内部技术择优的独立模块，或用候选总排名替代逐问求解叙事。
- 正文仍有占位符。
- 正文泄露内部工作流文件名。
- 引用的图片不存在。
- 关键数值与结果记录冲突。
- 编译器可用但论文编译失败。
- 编译后的 PDF 为空、缺页、页数异常或页面尺寸异常且无法解释。
- 视觉检查发现正文、表格、图片、公式、页眉页脚、页码等关键元素重叠、裁切、越界或乱码。
- 最终 PDF 从引言到结论的任一正文页缺少服务于该页论证且按实际尺寸可读的图或表。
- 完整论文正文图件总数不足 12 张、概念图不足 4 张，或数据图不足 5 张。
- 完整论文缺少以下任一项：Image2 文生图背景、Image2 总体解题路线图、Image2 机制阐释图或系统工作图、非常规数据图。机制图或承担相同用途的系统工作图使用向量绘制或将 Image2 成图转为向量，也属于硬错误。Image2 必需图待用户决定时，记录为未就绪，待齐备后复验。
- 完整论文的总体解题路线图未在引言的总体思路小节首次引用并嵌入，或图及图题在 PDF 中越过下一正文一级标题。
- 总体解题路线图的板块与小问未一一对应，遗漏逐问表中的公式、约束、求解步骤、结果或检验，缺少可辨识图示，或者缺失关键跨问联系、画出了与实际模型不一致的依赖。
- 总体解题路线图修订使用了缩写提示词，或成稿将原有独立项目概括、合并、隐藏或缩小到无法阅读，使信息量或细粒度低于核验通过的完整版。

## 警告标准

以下问题可判定为 `WARN`，但应尽量修复：

- 未引用的备用图片。
- 某章节过短或明显不均衡。
- caption 偏长。
- 参考文献偏少。
- 图表后解释文字不足。
- 仍有需要修正的全篇风格或图文版面问题。
- 视觉检查工具不可用，但已经记录原因并完成基础 PDF 元数据检查。
- 代码完整复现耗时过长，只做了轻量检查。
