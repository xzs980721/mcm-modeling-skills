# 阶段自检（stage checks）

每个阶段结束时跑一次轻量自检：**只查本阶段能改的东西**，不提前判后面阶段的问题。目的是在代价最低的时候发现方向性错误。

判定只有三档：

- `pass` —— 全部条目满足，继续下一阶段
- `conditional` —— 有缺口但不阻断，记入 `reports/STAGE_CHECK.md` 后继续
- `return` —— 有阻断项，回本阶段修，最多 2 轮（见 `_references/thresholds.md` 第四节）

每个条目的判据必须能给证据（文件、节号、行、数）。给不出证据的一律记 `unknown`，不算通过也不算失败，但要写进缺口清单。

---

## Stage 0｜brief 之后（选题前）

| 编号 | 检查 | 判据 |
|---|---|---|
| S0-1 | 题号已定 | 用户明确选择，写入 `AWARD_BRIEF.md` 的 `problem` 字段 |
| S0-2 | 评委怀疑清单已落到本题 | 八问每条都有"本题的答案形态"，不是通用问句 |
| S0-3 | 动作清单分了两层 | floor / strong 各自有 `n/N` 依据 |
| S0-4 | 别学清单已按本题裁剪 | 不超过 6 条，且每条与本题相关 |

阻断项：S0-1、S0-2。

---

## Stage 1｜plan 之后（1start）

| 编号 | 检查 | 判据 |
|---|---|---|
| S1-1 | 每个模型方向能对上 brief 的动作 | `plan.md` 里逐条标注对应的 brief 条目，或写明偏离理由 |
| S1-2 | 图表清单已排 | 数量达到题号下限（见 thresholds 第一节），每图写明论证用途 |
| S1-3 | 时间盒已分配 | 含三个门禁时刻（选题后、模型方向锁定、提交前） |
| S1-4 | 引擎与配色已定 | 写入 `plan.md`，配色含 HEX 与语义 |

阻断项：S1-1、S1-2。

---

## Stage 2｜建模报告之后（2analysis）

| 编号 | 检查 | 判据 |
|---|---|---|
| S2-1 | 子问题清单完整 | 含未编号问询；与题面原文逐条对应 |
| S2-2 | 每问四件齐 | 模型、参数来源计划、检验方式、预期输出形态（数／区间／方案） |
| S2-3 | 假设逐条附理由 | 无"裸假设"；理由指出现象依据或数据依据 |
| S2-4 | 有取舍记录 | 每个主方法至少一条"考虑过但没选"的理由 |
| S2-5 | 共享基础边界清楚 | 哪些复用、哪些扩展、跨问接口是什么 |
| S2-6 | 选型记录带往年依据 | 写了该题该方法的出现率或常见失败方式 |

阻断项：S2-2、S2-3。缺检验设计属阻断——它是后期最贵的返工。

---

## Stage 3｜求解与数据图之后（3coding）

| 编号 | 检查 | 判据 |
|---|---|---|
| S3-1 | 每问都有可运行产出 | 结果文件存在且与问号对应 |
| S3-2 | 约束与口径校验已做 | 报告里有校验记录，不是"应当满足" |
| S3-3 | 至少一项检验真实跑过 | 扰动／交叉验证／消融／回代，有数有图 |
| S3-4 | 参数可追溯 | 每个关键参数能指到代码行或数据来源 |
| S3-5 | 结果报告有摘要头 | ≤ 15 行，含各问关键数字 |
| S3-6 | 数据图达标 | 数量与每图论旨 |

阻断项：S3-2、S3-3。没有检验就被迫进写作阶段，是最常见的崩溃点。

---

## Stage 4｜概念图之后（4concept）

| 编号 | 检查 | 判据 |
|---|---|---|
| S4-1 | 三类必需图齐 | 背景图、总体路线图、机制图或系统工作图 |
| S4-2 | 每图有正文位置 | 写清在哪一章哪一节引用 |
| S4-3 | 与 plan 的配色一致 | 抽查两图的实际色值 |
| S4-4 | 降级已记录 | 若用向量替代 Image2，`plan.md` 与报告里写明原因与影响 |

阻断项：S4-1。

---

## Stage 5｜成稿之后（5writing）

| 编号 | 检查 | 判据 |
|---|---|---|
| S5-1 | 七章结构未偏移 | `check_sections.py` 通过 |
| S5-2 | 摘要自成一篇 | 含方法链、逐问数字结论、一句检验、一句结论 |
| S5-3 | 结论逐问回扣 | 每个子问题都能在结论里找到对应句 |
| S5-4 | 假设在后文被用到 | 至少标注每条假设的使用位置 |
| S5-5 | 无孤儿图 | 每张图都被正文引用 |
| S5-6 | 摘要词数在区间内 | 见 thresholds 第一节 |

阻断项：S5-1、S5-2。摘要不合格直接换档，没有补救空间。

---

## Stage 6｜交付之前（6verify）

不再用这套轻量检查，改跑 `mcm-judge` 的 review 模式（完整六维 + Gate）。判定与回退规则见 `mcm-judge/references/contract.md`。

## 增量节奏（tick / gate）

每个阶段分两层检查，避免"一次做完再判"导致的返工，也避免"每写一行就判"导致的空转：

| 层 | 什么时候 | 查什么 | 输出 |
|---|---|---|---|
| **tick** | 每完成一个增量 | 该增量的 2–3 条 + 已通过项是否被破坏 | 表格一行，最多一条改法 |
| **gate** | 阶段收尾、进下一阶段前 | 该阶段全部条目 + 遗留 | 判定 pass / conditional / return |

各阶段的增量划分：

| 阶段 | 增量 | tick 次数 | 理由 |
|---|---|---|---|
| S0 brief | 整份 | 1 | 单个产物，没有可切的增量 |
| S1 plan | 整份 | 1 | 同上 |
| S2 建模 | **每小问一个** + 收尾 1（跨问一致性与共享基础） | n+1 | 某问模型错了，它的代码和正文段落全废；按问切最省 |
| S3 求解 | **每小问一个**（跑通 + 校验 + 该问检验） | n | 同上，且可并行 |
| S4 概念图 | **每批 2 张**（或三类必需图各一批） | 2–3 | 图之间独立性高，切太细只是重复读同一份风格参数 |
| S5 写作 | **按批**：前置章（引言/假设/模型设计）1 批 + Solution 按小问 + 收尾章（检验/优劣势/结论）1 批 + **摘要最后单独 1 次** | n + 3 | 按节切太碎，同一批共享术语与符号；摘要依赖全文数字，必须最后做 |
| S6 review | 不适用 | 0 | 由 review 模式整体评 |

防抖动四条（这是"增量检查"能不能省钱的关键）：

1. **先立清单再干活。** 阶段开始时把该阶段的条目抄进 `reports/STAGE_CHECK.md` 作为空表，增量开始前先确认对应条目。**检查是核对，不是重议标准。**
2. **tick 不改标准。** 标准来自 Stage 0 的 brief 与本阶段冻结的清单。tick 只能判"符不符合"，不能提出"我们换个方向"——那是 gate 或人的事。
3. **tick 失败只给一条改法。** 给两条说明该增量切得太大，先切分。
4. **同一增量最多 2 次 tick**（上限见 [数值口径](../_references/thresholds.md) 第四节）。第 3 次直接记遗留，不纠缠。
## 执行约定

1. 结果写到 `reports/STAGE_CHECK.md`，按阶段、按增量追加，不覆盖历史（保留迭代记录）。tick 用紧凑表格，gate 用完整小节。
2. 每个阶段开始前先读上一阶段的"遗留"节，确认是否已修；同时把本阶段条目抄成空表待填。
3. `gate` 判 `return` 时必须给出**不超过 3 条**改法，按代价排序。超过 3 条说明该拆阶段，而不是让人一次改十件。
4. 同一阶段最多回退 2 轮；两轮仍未 `pass` 时，把未通过项写入"遗留"节并继续——比赛不能卡死，但缺口必须留痕，供 6verify 与最终评审参考。
5. **检查预算**：每阶段 tick 次数上限见 [数值口径](../_references/thresholds.md) 第四节。超预算的部分并入 gate，不再单独 tick——超过上限就说明增量切得太碎。
