# 美赛评奖标准

## 先选模式

| 用户在做 | 用 | 产出 |
|---|---|---|
| 刚拿到题面、要定方向、问"怎么做才可能拿奖" | brief | `reports/AWARD_BRIEF.md` |
| 一个阶段刚做完、问"能不能进下一步" | check | `reports/STAGE_CHECK.md`（追加） |
| 已有稿子、问"能拿什么奖 / 怎么改" | review | `reports/JUDGE_REVIEW.md` |
| 比赛全程 | brief → check×5 → review | 三份文件 |

两个模式都必须引用 `references/` 里的实测分布作为依据。只讲道理的评语没有价值——用户拿不到"改哪里、改成什么"。

## 依据从哪来

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `references/findings.md` | **蒸馏结论：22 条带数据的判断**（规模、摘要、检验、结构、年代、内容层） | 每次先读这一份 |
| `references/stage-checks.md` | **五个阶段的轻量自检条目**（S0–S5，含阻断项） | check 模式必读 |
| `references/calibration.md` | 变异测试结果：哪几维能自动测、哪几维必须人工判 | 想改评分卡之前读 |
| `references/o-features.md` | 总览表：各题规模与章节出现率 | 需要查具体数字时 |
| `references/problems/A.md` … `F.md` | 分题号的分布与逐年漂移 | 确定题号后**只读对应那一个** |
| `references/rubric.md` | 六维评分卡与 0–10 锚点 | brief 定动作、review 打分 |
| `references/judge-questions.md` | 评委预设怀疑清单（通用 + 分题型） | brief 第 2 节、review 诊断 |
| `references/anti-patterns.md` | 别学清单 | brief 第 4 节、review 扣分 |
| `references/exemplars.md` | 真实摘录（摘要开头、论证句式、图注） | 需要给"长这样"的样例时 |
| `references/contract.md` | 两份交接文件的字段格式 | 写产出前必读 |

## brief 模式

动笔前的窗口通常只有 1–3 小时，所以产出必须能一口气读完。

1. 读题面与附件，判题型：A 机理连续、B 离散优化、C 数据驱动、D 网络运筹、E 环境政策评价、F 政策策略。
2. 读 `o-features.md` + 对应题号文件，取本题的规模区间与动作出现率。
3. 出八条评委怀疑（见 `judge-questions.md`），每条附"可接受的答案形态"，不是空问句。
4. 按两层列必须命中的动作：**floor**（该题 ≥95% 的 O 奖论文都有，缺了直接降档）与 **strong**（60–95%，做了明显加分）。每条带 `n/N` 依据。
5. 出别学清单：语料里出现过、但不该模仿的做法（常见是把某篇的个性当标准）。
6. 写 `reports/AWARD_BRIEF.md`，格式严格照 `contract.md`。

纪律：
- 每条建议必须带数字依据。写"建议做灵敏度分析"是无效建议；写"检验章：A 题 51/52 篇有（98%），其中 60% 是独立小节、40% 并入结论前一段"才是依据。
- 不替用户选模型。给候选、给取舍标准、给"这类题往年偏什么"，选择权留给人。
- 全篇超过 150 行即失败。

## check 模式

用于阶段之间的闸门：一个阶段刚做完，判定能不能进下一步，并把意见反馈回该阶段。

1. 读 `references/stage-checks.md` 中对应的那一节（S0–S5），**只查那一节**。
2. 逐条给 `pass` / `gap` / `unknown`，每条附证据位置（文件、节号、数字）。给不出证据就是 `unknown`，不许猜。
3. 按阻断项判定整阶段：无阻断缺口 = `pass`；有非阻断缺口 = `conditional`；有阻断缺口 = `return`。
4. `return` 时给**不超过 3 条**改法，按代价排序，每条写明改哪个文件、改成什么、依据哪条阈值。
5. 追加写入 `reports/STAGE_CHECK.md`（不覆盖历史），格式见 `contract.md`。

纪律：

- 不提前判后面阶段的问题。写稿阶段发现"模型选错了"不是本阶段的事，记进缺口但不阻断。
- 不重复 `6verify` 的机检项（编译、章节结构、图件存在性）。这里只判"这一步做对了没有"。
- 同一阶段最多回退 2 轮（见 `_references/thresholds.md`），超限就记缺口前进，比赛不能卡死。

## review 模式

1. **Gate 先行**：五条合规项（25 页含附录、页眉、无身份信息、全英文、AI 报告已附）。任一 fail 只出 Gate 节，不打分——这些项不通过，后面的分数没有意义。
2. 按 `rubric.md` 六维打分。每维必须给三样：一句判据、一个证据位置（页/节/句）、一个对照数字。
3. 与本题 O 奖分位对照：页数、图表数、摘要词数各落在什么分位；缺了哪些 floor 动作、缺了哪些 strong 动作。
4. 出改法表，按"可回收分数"降序。每条写清：改哪一段、改成什么、依据哪条分布。
5. 写 `reports/JUDGE_REVIEW.md`。

纪律：
- 每条扣分必须有原文引用。引不出原文的问题不扣分。
- 档位只给三档（接近 O 奖 / M–F 之间 / H 以下），不给概率，不说"必中"。
- 不评"AI 味""读起来顺不顺"这类无指向的属性；只评能落到具体句子的性质。

## 与管线其他技能的边界

| 事情 | 谁负责 |
|---|---|
| 编译、七章结构、图数、页眉、一致性 | `6verify/scripts/writing_check.sh` |
| 改稿、写代码、画数据图、画概念图 | `5writing` / `3coding-visual` / `4concept-visual` |
| 单篇论文的做法挖掘 | `mcm-paper-cards`（本技能只告诉它该看哪几篇） |
| 评奖标准的判断与打分 | 本技能 |

本技能**只读不写**：不修改 `paper/`、`code/`、`results/` 里的任何东西。改稿一律交给 `5writing`。

## 语料的局限（每次输出都要交代）

- 语料**只有 O 奖**，没有 F/M/H 对照。所以本技能判的是"像不像 O 奖"，判不了"够不够格被淘汰"。这是结构性局限，不要用语气掩盖。
- 统计跨 2017–2025，格式规范（页数、图数、摘要长度）逐年变化。评格式时只用最近三年，评论证方式时才用全量。
- 语义类字段（论证类型、摘要首句类型）由规则抽取，存在误判。引用这类结论前要回原文核。
