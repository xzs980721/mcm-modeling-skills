# 美赛论文图表工作流

## 先按论文论证规划

在 `plan.md` 记录每张图或表的拟用章节、要回答的问题、数据或依据、图型、文件名和状态。完整美赛流程或单独执行完整阶段时，纳入相应的必需图件。仅制作、修改或导出指定图件时，按请求范围处理，并沿用可用的现有风格。

- 引言安排至少一张经审核的内置 Image2 文生图背景，例如题目场景或关键对象示意。
- 引言靠后的位置安排至少一张由 Image2 生成的[总体解题路线图](../mcm-solution-roadmap/SKILL.md)，接在总体思路的介绍及首次图号引用后。每个小问有独立的流程板块，图中说明跨问联系并配有可辨识的图示。成稿中路线图须完整出现在引言之后的第一个正文一级标题之前。
- 方法部分安排至少一张用内置 Image2 生成的机制阐释图或系统工作图，优先展示创新机制及其作用。
- 数据分析或结果安排至少一张有独立表达价值的非常规数据图，例如适合数据结构的非常规图型，或能直接展示额外关系的组合图。其余结果逐问覆盖关键证据。
- 验证优先展示能回答具体小问、说明扩展必要性或支持结论的基线比较、极端情景、消融和灵敏度。可以用同尺度多面板组织可比结果。

## 正文图件数量与计数

完整论文从引言到结论至少入稿 12 张图，其中概念图至少 4 张、数据图至少 5 张。两类下限之外至少再安排 3 张图，按论证需要灵活分配。概念图须覆盖背景、总体解题路线、机制阐释或系统工作三类独立图件，并至少再有一张承担独立任务的概念图。数据图至少有一张有独立表达价值的非常规图。

在 `plan.md` 的图表清单逐图登记类别、所属阶段、正文位置、要支撑的结论与来源，并记下概念图、数据图及总数。单独执行完整数据图或概念图阶段时，分别交付至少 5 张数据图或至少 4 张概念图，并满足该类必需图要求。只制作、修改或导出指定图件时按请求范围执行。

最终按正文实际入稿、具有独立图号、可读且承担独立论证任务的图计数。多面板合图计一张，同一图只计入一个类别。按主要论证用途判定混合图件的类别。分拆同一结果、重复使用同图或装饰性素材不增加计数。表格继续用于逐页图表覆盖，图件总量单独核算。

## 正文逐页图表覆盖与版面平衡

最终 PDF 从引言到结论的每一页都须有至少一幅服务于本页论证、按实际尺寸可读的图，或一张这样的表。只有标题、段落、列表、公式或装饰元素的正文页视为纯文字页。摘要页、目录、参考文献、独立信件或备忘录、附录和 AI 使用报告按各自的用途和提交要求排版。

遇到纯文字页，按该页论证选择一种补充方式。

- **概念图。** 需要帮助读者理解场景时补题目背景图，需要理解各问联系时制作总体解题路线图，需要解释因果、结构或流程时补机制阐释图或系统工作图。按规定交给 `4concept-visual` 出图。总体解题路线图只安排在引言的总体思路小节。
- **数据图。** 需要展示趋势、差异、分布或权衡时，从可追溯的数据或计算结果绘图，交给 `mcm-data-figure`，涉及新增求解时返回 `3coding-visual`。
- **三线表。** 需要紧凑对照假设、方案、场景、参数或结果时，由 `5writing` 用论文原生表格排成顶线、表头分隔线和底线，搭配清楚的表头、单位及英文表题。

结合图表调整段落与分页，保持论述、图表和图题或表题相邻。统一对齐、宽度、字号和边距，检查相邻页的图文疏密。用实际尺寸复核可读性，避免用无关图片、重复图表、过小的图表或占位元素凑数。每次重排后按最终 PDF 重新检查全部正文页。

## 检索并核对图表知识卡

优先使用用户或 `plan.md` 指定的知识卡根目录。没有指定时，检查美赛工作区内的 `美赛范文_2006-2025/知识卡片/`，从其 `visualization/` 检索。沿用已有卡片字段，用标题、标签、论证任务、图型与输入、视觉编码、重绘与迁移做组合检索。按需要扩展中英文表达，例如用「总工作流程」「模型总览」「Our Work」「workflow」拓展总体路线图的召回。图件类型依据卡片正文和原图判定。

非常规数据图、机制阐释图或系统工作图按表达任务返回 5 张经核对的候选卡。使用同一图型与编码的一组图可共享一次检索。总体解题路线图直接采用锁定母版。仅调色或重新导出时沿用已有选型记录。

1. 按当前任务的表达目的和适配度筛选。数据图优先检索能揭示额外关系的非常规图型或组合编码，适配度相近时再参考卡片评分。同一原图的整图卡和面板卡通常合为一个候选。
2. 按卡片的 `source.pdf_root`、`source.pdf` 和 `source.pdf_pages` 定位 PDF，查看原图及图题，并阅读原文中解释该图的段落。用图号或面板号记录出处，无编号图记下页内位置。无法核对或不符合任务前提时，依次核对后续候选补位。
3. 在对应阶段报告列出候选卡 ID 或名称、原文页码和图号、适用理由及可借鉴做法，标明选中项、本题改动和成稿路径。少于 5 张时记录实际数量和原因。知识库不可用或没有合适的卡时，从当前题目、模型或数据独立设计，记录选择依据。

## 由用户选择整篇论文的图表风格

为全篇图表确定一套全局配色。用户已指定预设、自定义风格或参考图时，沿用其选择并落实为色值。需要配色候选时，在浏览器打开 [ColorDrop 生成器](https://colordrop.io/palette/create)，用公开赛题主题、图表用途和视觉风格关键词生成 2–3 套，展示色板及 HEX 色值供用户确认。ColorDrop 会公开生成的色板，提示词只使用公开主题和视觉描述，例如 `lunar settlement, aerospace engineering, muted colors, high contrast on white paper`。网站不可用时，提供本地预设或接受用户给出的色板。

把确认的色板来源、HEX 色值与各自用途写入 `plan.md` 的「论文图表风格」；采用 ColorDrop 时一并记录关键词，保留可用的色板链接。将颜色分配给主模型、基线、情景、风险或其他本题实际使用的语义，核对实际阅读尺寸及灰度下的可区分性，必要时加上线型、形状或文字标记。单独处理图件时沿用已确认色板，缺少色板时请用户选定，没有 `plan.md` 时将选择记入交付说明。

全局色板用于数据图、概念图、着色表格和总体解题路线图。总体解题路线图使用 [固定英文母版](../mcm-solution-roadmap/references/image2-template.txt) 的布局及视觉规范，在提示词的配色段填入已确认的全局色值和对应语义。

把选择落实为可跨阶段复用的参数，包括风格名或参考来源、适合版心的常用图宽、渲染后文字大小和字体、主题色和强调色，以及基线、候选和各情景的固定颜色、线型或标记。统一数值精度、单位、面板标签、线宽、图例和边距。同一对象在数据图、概念图与表格中保持名称和颜色语义一致。关键对照使用线型、形状或文字辅助辨认。

## 按图件类型使用 nature-figure

需要下方 `nature-figure` 路线时，优先读取当前环境已启用的 `nature-figure` 的 `SKILL.md`。同一工作区若提供了本地副本，也可沿用。资源和脚本路径从实际的 skill 目录解析。依赖缺失时记录具体缺项，并继续独立的分析、计算或写作。

- 数据图从计算结果生成定量矢量层，可按 [内置 Image2 路线](#使用内置-image2-生成图) 探索布局或生成非定量插画层。按 `nature-figure` 选择 Python 或 R，运行适用的源文件、最终 PDF、碰撞和多面板对齐检查。
- 总体解题路线图由 [mcm-solution-roadmap](../mcm-solution-roadmap/SKILL.md) 填写锁定母版，完整阶段由 `4concept-visual` 将生成的提示词原样交给内置 Image2。用于解释机制、系统结构和系统关系的图使用[内置 Image2 路线](#使用内置-image2-生成图)生成最终稿，保留成图，禁止转为向量或改为向量绘制。独立的算法或任务流程图可用[向量示意图路线](#绘制向量示意图)。

### 绘制向量示意图

补充的算法或任务流程图可读取 `nature-figure` 的 `references/vector-schematic-workflow.md` 和 `references/vector-schematic-style-rules.md`。汇总正文位置、主要关系、英文术语和风格，请用户集中确认简述。保留可编辑 SVG，运行 `scripts/audit_svg_schematic.py`，导出论文用矢量 PDF，按实际版面宽度检查标签、箭头、对齐和留白。

### 使用内置 Image2 生成图

1. 读取 `nature-figure` 的 `references/ai-graphical-abstract-workflow.md`。基于本题内容和已确认风格写英文简述，明确对象、关系、构图、画幅、背景和避用元素。需要纳入论文时，核查当届 COMAP 规则和披露要求。
2. 用实际 `nature-figure` 目录下的 `scripts/generate_openrouter_schematic.py` 离线生成 JSON。风格传给 `--style`，简述传给 `--prompt-file`，按需补充 `--title` 和 `--panel-map`，加 `--dry-run` 保留标准模板及科学约束。
3. 提取 JSON 的 `prompt` 原样传给 Codex 内置 Image2（`gpt-image-2`）。获准使用的参考图可随提示词传入。画幅等要求写在简述里，以实测成图规格为准。
4. 对照题面或模型核对对象、关系、方向和文字。保存完整提示词、模型和调用渠道、图件及审核记录。修订时更新简述，重新生成完整提示词。

## 先核实内容，再迭代视觉

1. 渲染初稿。核对每条数据序列、单位与刻度，核对图示的对象、箭头和关系是否有题面或报告依据。
2. 按统一风格美化。检查对齐、层级、留白、图例和标注位置。相关面板采用可直接比较的尺度和顺序，轴范围、聚合或变换有明确理由时在图题或正文中说明。
3. 在计划使用的论文宽度查看，检查缩小后文字、线条、色差和局部拥挤。修图后重新导出。在阶段报告中保存代表性的初稿与定稿位置及具体改动。初稿和诊断图可放在 `figures/drafts/`。
4. 论文编译后再次逐页查看。优先修源图，再重新嵌入并编译。核查图题、正文引用、图表可读性和跨章节的一致性。
