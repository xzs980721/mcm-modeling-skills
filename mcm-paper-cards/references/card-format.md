# 知识卡格式

## 文件名与索引

| 类型 | 目录 | 文件名 |
| --- | --- | --- |
| 建模方法卡 | `modeling/` | `modeling-<PDF指纹前12位>-<主题短名>.md` |
| 图表方法卡 | `visualization/` | `visualization-<PDF指纹前12位>-<主题短名>.md` |

PDF 指纹是文件的 SHA-256。主题短名使用小写英文、数字和连字符，反映卡片讲的做法。写入前按 PDF 指纹和具体做法检查重复。既有文件需要修订时，保留原记录，按用户指定的更新方式处理。

两类卡片使用以下 YAML 元数据。示例值是占位说明，写入时使用实际值。范文库根目录已知时，`source.pdf` 记录库内相对路径，`source.pdf_root` 记录根目录。仓库分发的卡片保留库内相对路径，`source.pdf_root` 填 `null` 表示原论文库待配置。只有单篇 PDF 路径且没有库内相对路径时，可使用绝对路径并将 `source.pdf_root` 填 `null`。路径分隔符统一为 `/`。未知的年份、题号填 `null`，PDF 物理页码按从小到大列出，可用正文注明印刷页码。

```yaml
---
schema: mcm-card-v1
id: 'modeling-<PDF指纹前12位>-<主题短名>'
type: modeling
title: '<一句话写清可迁移的做法>'
paper:
  title: '<论文标题>'
  year: null
  problem: null
source:
  pdf: '<PDF路径>'
  pdf_root: null
  sha256: '<完整SHA-256>'
  pdf_pages: [1]
tags: ['<任务类型>', '<机制或表达目的>', '<方法或图型>']
score:
  total: 0
  max: 20
  tier: reference
---
```

图表卡的 `type` 为 `visualization`，`id` 前缀与文件名一致。标签写具体术语，可保留原文英文关键词。比如，建设运输问题可以用「资源调度」「容量约束」「不确定性」，可行边界图可以用「权衡」「可行域」「可比情景」。

## 建模方法卡正文

```markdown
# <可迁移做法>

## 原题与基线
<任务、决策对象、数据和关键约束。列出作者实际使用的基线，未报告时明示。>

## 建模机制与求解
<假设、输入及单位、变量、目标或关系、关键约束和求解步骤。标明新增机制改变了什么。>

## 验证与局限
<验证对象、比较口径、证据和结果。列出来源缺项、失败情景或可复现性限制。>

## 迁移到新题
<适用前提、需要替换的输入或约束、一个最小可行检验，以及停用条件。>

## 证据定位
- PDF 第 <n> 页，<节、公式、表或图号> · <支持哪项判断>

## 评分
| 维度 | 分数（0–4） | 依据或缺口 |
| --- | --- | --- |
| 证据可追溯性 | <分数> | <原页定位与对应证据> |
| 机制解释力 | <分数> | <依据> |
| 实现可复现性 | <分数> | <依据> |
| 验证质量 | <分数> | <依据> |
| 可迁移性 | <分数> | <依据> |

总分 **<总分>/20** · <分档中文名>
```

## 图表方法卡正文

```markdown
# <可迁移图表做法>

## 入选理由
<表达创新、视觉张力或两者。指出哪张图、哪个面板体现了什么做法，以及它让读者更容易理解什么。>

## 论证任务
<图在正文的位置、要回答的问题、读者应能判断的关系或结论。>

## 图型与输入
<图型、面板角色、数据粒度、字段及单位，或概念对象和关系。记录可取得及缺失的输入。>

## 视觉编码
<位置、颜色、线型或标记、坐标/尺度、图例、阅读顺序及标题位置。>

## 重绘与迁移
<同类新题的最小输入和绘制步骤。给出容易误读的情形、实际尺寸检查和可借鉴的风格。>

## 证据定位
- PDF 第 <n> 页，<图号和面板，必要时加正文解释页> · <支持哪项判断>

## 评分
| 维度 | 分数（0–4） | 依据或缺口 |
| --- | --- | --- |
| 证据可追溯性 | <分数> | <原页、图号及对应证据> |
| 论证表达 | <分数> | <依据> |
| 重绘可行性 | <分数> | <依据> |
| 视觉可读性 | <分数> | <依据> |
| 可迁移性 | <分数> | <依据> |

总分 **<总分>/20** · <分档中文名>
```
